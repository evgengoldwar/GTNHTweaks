# GTNHTweaks

Модульный мод-твикер для GT: New Horizons (Minecraft 1.7.10).

## Модули

Каждый модуль лежит в своей папке `src/main/java/gtnhtweaks/modules/<модуль>` и наследует
`gtnhtweaks.core.TweakModule`. Новые модули регистрируются в `gtnhtweaks.core.ModuleManager`.
Миксины модуля лежат в `src/main/java/gtnhtweaks/mixins/early/<модуль>` (для классов других модов —
в `src/main/java/gtnhtweaks/mixins/late/<модуль>`, пакет миксинов общий для мода)
и подключаются в `gtnhtweaks.mixins.Mixins` только когда модуль включён.
Общий стиль (темы `SHADOW`/`DARK`/`LIGHT`, логотип GTNH, кнопки, панели) лежит в `src/main/java/gtnhtweaks/common/render`,
общие миксины — в `src/main/java/gtnhtweaks/mixins/early/common`.

Конфиги (`config/GTNHTweaks/`):

| Файл | Что настраивает |
| --- | --- |
| `modules.cfg` | включение и отключение модулей |
| `<id модуля>.cfg` | настройки конкретного модуля |

Настройки удобнее менять в окне настроек мода: клавиша **F7** в игре (меняется в «Управлении»,
раздел GTNHTweaks), кнопка в главном меню или «Config» в списке модов. Слева — модули с переключателями,
справа — настройки выбранного модуля: переключатели, выбор из вариантов, поля ввода, редактор списков,
сброс к значению по умолчанию, подсказки при наведении и поиск по всем настройкам (Ctrl+F).
Изменения сохраняются и применяются сразу. Включение и отключение модулей и настройки,
помеченные как требующие перезапуска, вступают в силу после перезапуска игры: окно их перечисляет внизу.

### loadingscreen: экран загрузки

Заменяет экран загрузки Minecraft:

- вместо логотипа Mojang рисуется логотип **GTNH**;
- полосы прогресса загрузки модов;
- таймер загрузки сборки (от старта JVM до главного меню);
- время предыдущего запуска и сколько процентов от него уже прошло;
- использование памяти;
- стена из блоков на фоне: пока игра грузится, она по рядам снизу вверх выкладывается из блоков Minecraft
  и случайных блоков модов из папки `mods` (текстуры читаются прямо из jar-файлов). Когда загрузка заканчивается,
  стена достраивается, текст гаснет, стена рушится и за ней открывается главное меню;
- время загрузки в левом верхнем углу главного меню (если модуль `mainmenu` выключен,
  иначе его показывает главное меню).

Работает со всеми вариантами экрана загрузки:

- ванильный экран Mojang до загрузки модов;
- сплэш Forge (`config/splash.properties`, `enabled=true`);
- BetterLoadingScreen (есть в GTNH): он продолжает отслеживать прогресс,
  а этот модуль рисует свой экран поверх каждого его кадра.

Настройки в `config/GTNHTweaks/loadingscreen.cfg`:

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `general/theme` | `SHADOW` | тема: `SHADOW` (серый объёмный стиль Shadow UI), `DARK` (тёмный) или `LIGHT` (светлый) |
| `general/showTimer` | `true` | таймер загрузки |
| `general/showPreviousLaunch` | `true` | время предыдущего запуска |
| `general/showMemory` | `true` | использование памяти |
| `general/showLoadTimeInMainMenu` | `true` | время загрузки в главном меню |
| `wall/buildWall` | `true` | стена из блоков на фоне экрана загрузки |
| `wall/modBlocks` | `true` | брать в стену и блоки модов, а не только ванильные |
| `wall/modBlockShare` | `60` | доля блоков модов в стене, в процентах |
| `wall/rows` | `9` | сколько рядов блоков по высоте экрана (4–30) |
| `wall/textVeil` | `70` | насколько фон перекрывает стену во время загрузки, в процентах, чтобы текст читался |
| `wall/crumbleAtEnd` | `true` | в конце загрузки текст гаснет, а стена рушится, открывая главное меню |
| `wall/crumbleSpeed` | `100` | скорость финальной анимации в процентах (25–400, `200` — вдвое быстрее) |
| `wall/crumbleSound` | `true` | звук обрушения стены |
| `integration/replaceVanillaScreen` | `true` | заменять экран с логотипом Mojang |
| `integration/replaceForgeSplash` | `true` | рисовать поверх сплэша Forge |
| `integration/drawOverBetterLoadingScreen` | `true` | рисовать поверх BetterLoadingScreen |
| `text/*` | английский | подписи на экране, поддерживается кириллица |
| `text/unitHours`, `unitMinutes`, `unitSeconds` | `h`, `min`, `s` | единицы времени запуска в главном меню (например `ч`, `мин`, `с`) |

Время последней загрузки хранится в `config/GTNHTweaks/loadingscreen-stats.properties`.

### mainmenu: главное меню

Главное меню в том же стиле, что и экран загрузки:

- фон и логотип **GTNH** вместо панорамы и логотипа Minecraft;
- анимированная печатная плата на фоне: дорожки и микросхемы с выдавленной шестерёнкой GregTech, по которым бегут импульсы тока
  в цветах уровней напряжения GregTech; фон чуть сдвигается за мышью (отключается в разделе `circuit`);
- подпись под логотипом и пульсирующий жёлтый сплэш-текст в цвете темы;
- плоские кнопки в цветах темы с подсветкой при наведении;
- внизу слева копирайт Mojang, справа время запуска сборки, например «Loaded in 8.1 s»
  (нужен модуль `loadingscreen`). Строки версий Minecraft/MCP/FML/Forge не показываются.

Ванильное меню остаётся на месте: все кнопки работают как раньше, кнопки других модов сохраняются.
Обычные кнопки других модов рисуются в стиле GTNH, кнопки со своим классом рисуются сами.

Настройки в `config/GTNHTweaks/mainmenu.cfg`:

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `general/theme` | `SHADOW` | тема: `SHADOW`, `DARK` или `LIGHT` |
| `general/showSplashText` | `true` | сплэш-текст под логотипом |
| `general/showLoadTime` | `true` | время загрузки сборки |
| `general/yieldToResourcePacks` | `false` | если включённый ресурс-пак заменяет логотип Minecraft, панораму или кнопки — показывать ванильное меню с ресурс-паком |
| `circuit/showCircuit` | `true` | печатная плата на фоне |
| `circuit/currentColors` | `TIERS` | цвет импульсов: `TIERS` (цвета уровней GT, LV–UEV) или `THEME` (цвет темы) |
| `circuit/rows` | `18` | сколько клеток платы по высоте экрана (8–40): больше — мельче и гуще |
| `circuit/pulseSpeed` | `10` | скорость импульсов, клеток в секунду (1–30) |
| `circuit/brightness` | `65` | яркость дорожек и импульсов, в процентах (20–100) |
| `circuit/chips` | `true` | микросхемы на плате; в центре шестерёнки светится цвет уровня, при импульсе она вспыхивает |
| `circuit/parallax` | `true` | плата чуть сдвигается за мышью |
| `text/subtitle` | `GT: New Horizons` | подпись под логотипом, пусто чтобы скрыть |

### menus: все меню и инвентари

Все экраны Minecraft, Forge и FML в том же стиле, включая подменю настроек (графика, управление, звук...),
одиночную и сетевую игру, список модов, настройки модов (и экраны модов, наследующие их), язык,
а также игровые меню (пауза, настройки из игры).

Что меняется:

- фон темы вместо земли; в игре остаётся ванильное затемнение мира;
- списки: панель в цветах темы, рамка выделения цвета логотипа;
- кнопки, в том числе подклассы, только меняющие поведение (например «Super Secret Settings»),
  и ползунки (FOV, громкость, графика, ползунки настроек модов) — плоские, в цветах темы;
- поля ввода (адрес сервера, имя мира, поиск) — в цветах темы;
- белый и серый текст экранов перекрашивается в цвета темы (цветной текст остаётся),
  в светлом стиле тени текста отключаются. Подсказки (тултипы) и HUD не трогаются.

Инвентари: за ними остаётся ванильное затемнение мира. Текстуры ванильных инвентарей в темах `DARK` и `SHADOW`
затемняются в цвет панели темы (слоты сохраняют объём), заголовки становятся светлыми.
Инвентари модов сохраняют свои текстуры: у каждого мода они свои, общего способа перекрасить их нет.

Кнопки со своей отрисовкой (иконки, флажки, текстурные кнопки модов) остаются как есть.

Настройки в `config/GTNHTweaks/menus.cfg`:

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `general/theme` | `SHADOW` | тема: `SHADOW`, `DARK` или `LIGHT` |
| `general/recolorText` | `true` | перекрашивать белый и серый текст в цвета темы |
| `general/yieldToResourcePacks` | `false` | текстуры включённых ресурс-паков важнее темы, см. ниже |
| `general/fullFramerate` | `true` | лимит FPS из настроек графики в главном меню и других экранах вне мира вместо ванильных 30 FPS |
| `screens/themeVanillaScreens` | `true` | все экраны Minecraft/Forge/FML и экраны модов, наследующие их |
| `screens/themeInGame` | `true` | также меню в игре |
| `screens/themeInventories` | `true` | затемнение ванильных инвентарей |
| `screens/extraScreens` | пусто | классы экранов модов, которые тоже нужно оформить |
| `screens/excludedScreens` | чат, творческий инвентарь | классы экранов, которые остаются ванильными |

#### Ресурс-паки

Если `yieldToResourcePacks = true` и включённый ресурс-пак заменяет ванильную текстуру,
которую меняет мод, вместо темы показывается ресурс-пак:

| Текстура в ресурс-паке | Что тогда не меняется модом |
| --- | --- |
| `textures/gui/options_background.png` | фон экранов, списки, поля ввода и цвета текста |
| `textures/gui/widgets.png` | кнопки и ползунки |
| `textures/gui/title/minecraft.png`, панорама, `widgets.png` | главное меню целиком (модуль `mainmenu`) |

С `yieldToResourcePacks = false` (по умолчанию) тема рисуется всегда, и ресурс-паки на эти экраны не влияют.
Текстуру инвентаря, заменённую ресурс-паком (`textures/gui/container/...`), мод не затемняет никогда:
у пака уже свои цвета.
Учитываются только паки, включённые в меню ресурс-паков; ресурсы модов не считаются.
Экран загрузки не зависит от ресурс-паков: они загружаются уже после него.

### minecraft: твики самого Minecraft

**Обводка блока.** Обводку блока под курсором можно настроить: цвет с прозрачностью, толщину линий,
режим «сквозь блоки» (обводку видно через другие блоки, как каркас), заливку граней своим цветом
и радужный режим, в котором цвета линий переливаются вдоль обводки.
Включается опцией `blockOutline/enabled` в `minecraft.cfg` (после перезапуска). Тогда в «Управлении»,
раздел GTNHTweaks, появляется клавиша «Обводка блока» (по умолчанию **O**). Она открывает экран
с живым превью: блок камня вращается по кругу, чтобы обводку было видно со всех сторон, а если
установлен GregTech — рядом вращается труба GT с оверлеем ключа. Справа — цвет (поле HEX, ползунки
красного, зелёного, синего и прозрачности, готовые цвета), толщина, режим, заливка и кнопка «Vanilla»
для сброса. Изменения видны сразу и сохраняются при закрытии экрана. Оверлей инструментов GregTech
рисует обводку с теми же настройками.

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `blockOutline/enabled` | `false` | своя обводка и клавиша экрана настройки |
| `blockOutline/color` | `66000000` | цвет линий AARRGGBB (как в ванилле) |
| `blockOutline/width` | `2.0` | толщина линий в пикселях |
| `blockOutline/mode` | `NORMAL` | `NORMAL` — как в ванилле, `THROUGH_BLOCKS` — видно сквозь блоки |
| `blockOutline/fillColor` | `00000000` | цвет заливки граней AARRGGBB, прозрачность 00 — без заливки |
| `blockOutline/rainbow` | `false` | линии переливаются цветами радуги вдоль обводки |
| `blockOutline/rainbowSpeed` | `0.5` | скорость радуги, оборотов в секунду |

### itemphysics: физика выброшенных предметов

Выброшенные предметы больше не висят в воздухе и не крутятся на месте, а лежат на земле, как будто упали:

- плоские предметы лежат плашмя (с толщиной, как в ванилле), блоки стоят на грани;
- в полёте предмет кувыркается, тем быстрее, чем быстрее летит, а при падении теряет большую часть
  вращения и заваливается на ближайшую сторону по ходу вращения: немного покачивается и замирает;
- стак лежит кучкой до пяти штук: плоские предметы друг на друге со случайным сдвигом и поворотом,
  блоки рядом друг с другом (пятый сверху);
- у каждого предмета свой случайный поворот, поэтому одинаковые предметы не лежат одинаково;
- предмет не проваливается в пол: при наклоне он приподнимается ровно настолько, насколько опускается
  его нижняя точка; у стены или рядом с полублоком он плавно отодвигается, чтобы не входить в блоки;
- в воде медленно вращается, пока не опустится на дно;
- когда сервер поправляет место только что упавшего предмета, тот не прыгает, а плавно доезжает
  до нового места; от такой поправки предмет не начинает кувыркаться заново, а кучка при слиянии
  стаков не перекладывается;
- работают зачарованное свечение, цвета и многослойные иконки, предметы со своим рендером
  (предметы GregTech, модели блоков модов).

Меняется только отрисовка: предметы подбираются, летят и синхронизируются как в ванилле, поэтому
модуль работает и на серверах без мода. Предметы в рамках и «ненастоящие» предметы, которые моды рисуют
на своих блоках, остаются ванильными.

Настройки в `config/GTNHTweaks/itemphysics.cfg`:

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `items/tumbleInAir` | `true` | кувыркаться в полёте и заваливаться на бок при падении; выключено — падают плашмя |
| `items/tumbleSpeed` | `1.0` | скорость вращения в полёте (0.1–3) |
| `items/piles` | `true` | стак лежит кучкой до пяти штук |
| `items/keepOutOfBlocks` | `true` | отодвигать предметы от стен, чтобы они не входили в блоки |

### gregtech: твики GregTech

Работает только если установлен GregTech 5 Unofficial, иначе ничего не делает.

- Изолированные кабели, поставленные в мире, рисуются как обычные провода из того же материала:
  изоляции не видно. В инвентаре, в руке и выброшенными на землю они остаются изолированными.
  Меняется только текстура: толщина кабеля и его хитбокс прежние.
- Оверлей инструментов как в GregTech CEu Modern: когда с ключом, кусачками, отвёрткой, ломом,
  накладкой или трубой в руке наводишься на трубу, кабель или машину, вместо сетки GT5 рисуется
  пульсирующая сетка 3×3 с иконкой в каждой ячейке — что инструмент сделает с этой стороной:
  подключить или отключить трубу/провод, повернуть лицевую сторону или выход, поставить, снять или
  настроить накладку. Ячейка под курсором яркая, остальные полупрозрачные. С киянкой на машине
  показывается, работает она или на паузе, с молотом — заглушена ли. Когда сетка рисуется, решает
  GT5, как раньше; меняется только вид. Иконки взяты из GregTech CEu Modern (LGPL-3.0),
  звуки инструментов в GT5 и так те же, что в GTCEu.

Настройки в `config/GTNHTweaks/gregtech.cfg`:

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `cables/hideCableInsulation` | `true` | рисовать поставленные изолированные кабели без изоляции |
| `toolOverlay/modern` | `true` | оверлей инструментов как в GregTech CEu Modern; `false` — сетка GT5 |

### chromatictooltips: фиксы Chromatic Tooltips

Работает только если установлен [Chromatic Tooltips](https://github.com/slprime/ChromaticTooltips),
иначе ничего не делает. Чинит его вместе с
[Chromatic Tooltips Compat](https://github.com/slprime/ChromaticTooltipsCompat) и аддоном
[Chromatic Spectrum](https://github.com/Danastroovakim/ChromaticSpectrum):

- Chromatic Spectrum красит тултип в цвета предмета или жидкости, о которых он, а Compat передаёт
  тултипы окон ModularUI (баки GregTech и другие) и квестов BetterQuesting одним текстом, поэтому они
  оставались серыми. Теперь бак жидкости в окнах ModularUI 1 и 2 красится в цвет жидкости, а квест в
  BetterQuesting — в цвет своей иконки. Такой тултип берёт и тему ресурспака для этой жидкости или
  предмета (с иконкой), а не тему `default`, в которой может не быть маркерных цветов Chromatic Spectrum.
  Имя жидкости становится заголовком справа от иконки в цвете темы, как в NEI, а строка с ним
  убирается из текста ниже. Остальной текст тултипа не меняется, у квестов заголовком остаётся имя квеста.
- Текст в тултипах квестов BetterQuesting вылезал за рамку: Chromatic Tooltips меряет ширину строк
  заранее, а рисуются они шире. Теперь ширина каждой нарисованной строки запоминается, и рамка
  подстраивается под неё со следующего кадра (Chromatic Tooltips пересобирает тултип много раз в секунду).

Настройки в `config/GTNHTweaks/chromatictooltips.cfg` (нужен перезапуск):

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `fixes/colorTextTooltips` | `true` | красить тултипы бака ModularUI и квеста BetterQuesting (нужен Chromatic Spectrum) |
| `fixes/fitTextWidth` | `true` | растягивать рамку тултипа под нарисованный текст |

### extrautilities: твики Extra Utilities

Работает только если установлен Extra Utilities, иначе ничего не делает.

**Живой питомец вместо Healing Axe.** Лечащий топор рисуется маленьким живым существом, которое
моргает и улыбается, поворачиваясь лицом к тому, кто на него смотрит. Какое именно — выбирается
параметром `healingAxe/model`:

- `PLANT` — глиняный горшочек с растением: стебель покачивается, голова «дышит», время от времени
  растение радостно трясётся и смеётся; листья растут, желтеют, опадают рядом с горшком и вырастают заново.
- `AQUARIUM` — стеклянный аквариум с золотой рыбкой: она плавает по кругу, иногда подплывает
  к переднему стеклу посмотреть на игрока, водоросли колышутся, от камня поднимаются пузырьки.
- `SLIME` — слайм в стеклянной банке: прыгает, сплющиваясь и вытягиваясь, каждым третьим прыжком
  бьётся в крышку (крышка подскакивает), иногда прижимается лицом к стеклу.
- `LANTERN` — железный фонарь с духом-огоньком: огонёк покачивается, мерцает, оглядывается,
  в трубу летят искры, и он светится сам — не темнеет ночью. В Незере огонь становится синим,
  как у фонаря душ из новых версий: голубое пламя, искры, свечение и стекло. В руке фонарь **висит на ручке**,
  как в новых версиях: прямо вниз, куда бы ни смотрела камера, отстаёт при поворотах и ходьбе,
  раскачивается и успокаивается (у каждой руки и каждого игрока свой маятник).
- `PEASHOOTER` — горохострел в том же глиняном горшке: круглая голова с трубкой, большие глаза,
  хохолок на затылке, розетка листьев у земли. Смотрит на игрока вполоборота и каждые несколько секунд
  стреляет горошиной — с отдачей, раздувающейся трубкой и облачком у дула.
- `SUNFLOWER` — подсолнух в том же горшке: улыбающееся лицо в кольце жёлтых лепестков, весело качает
  головой. Раз в несколько секунд лицо загорается и он делает солнышко — оно поднимается над головой,
  вращаясь, и тает; солнышко светится само.

Рисуется в руке от первого и третьего лица, в инвентаре и выброшенным на землю — как блок.
С модом Backhand (GTNH) всё то же работает и для второй руки: и от первого лица, и на других игроках;
питомец во второй руке живёт своей жизнью, не синхронно с тем, что в первой. От первого лица горшочек,
горохострел, подсолнух, аквариум и банка стоят на ладони: их держит снизу рука игрока — та же, что ванилла рисует для пустой
руки (во второй руке Backhand — левая, как пустая вторая рука). Фонарь висит с пальцев той же ванильной
руки, на том же месте, что и пустая рука. Лицо смотрит на игрока, так что в правой руке повёрнуто влево, а в левой — вправо.

Питомец чувствует, где он, и всё наступает плавно — с закатом или с началом дождя. Даже если время
или погоду переключить командой (`/time set`, `/weather`) или унести его из пустыни, он засыпает,
просыпается и меняет настроение за пару секунд, а не мгновенно:

| | Ночью | Под дождём (если он падает прямо на него) | В жаре (пустыня, саванна, меза) и в Незере |
| --- | --- | --- | --- |
| Растение | спит, клюёт носом, «Zzz» | смотрит вверх, смеётся, падают капли | вянет, бледнеет, грустит, пот |
| Аквариум | рыбка спит неподвижно на песке | воды больше, рыбка время от времени выпрыгивает | воды мало, рыбка хватает воздух у поверхности |
| Слайм | спит лужицей, «Zzz» | прыгает чаще и смеётся | тает, растекается, капает |
| Горохострел | спит, не стреляет, «Zzz» | стреляет чаще, довольный | вянет, грустит, стреляет вяло мелким горохом |
| Подсолнух | спит, лепестки сложены, солнц нет | грустит, лепестки поникли, солнц меньше | сияет, солнц больше |
| Фонарь | огонёк дремлет и светит тусклее | съёживается, дрожит, испуганные глаза | разгорается, большой и счастливый; в Незере — синим огнём душ |

Модели рисуются кодом, без текстур, сам предмет не меняется. Настройки применяются сразу, без перезапуска.

Настройки в `config/GTNHTweaks/extrautilities.cfg`:

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `healingAxe/model` | `PLANT` | кто вместо топора: `PLANT`, `AQUARIUM`, `SLIME`, `LANTERN`, `PEASHOOTER`, `SUNFLOWER` |
| `healingAxe/inHand` | `true` | вместо топора в руках, вторая рука Backhand тоже |
| `healingAxe/holdingArm` | `true` | от первого лица его держит рука игрока, а не висит в воздухе |
| `healingAxe/moods` | `true` | реагирует на ночь, дождь и жару |
| `healingAxe/inInventory` | `true` | в слотах инвентаря |
| `healingAxe/onGround` | `true` | когда топор лежит на земле |

### logs: разобранные логи

Раскладывает лог игры по отдельным файлам в папке `GTNHTweaksLogs` в корне Minecraft,
чтобы ошибки и краши можно было найти сразу, без поиска в мусоре `fml-client-latest.log`.
Работает на клиенте и на сервере.

**Экран краша.** После краша игра не закрывается сразу, а показывает свой экран:
заголовок, описание и исключение, проблема простыми словами и наиболее вероятный мод-виновник,
две вкладки — «Problem» (тип проблемы с объяснением, что упало, моды в стеке, короткий стек,
последние ошибки лога) и «Crash report» (весь отчёт) — с прокруткой колесом, ползунком и клавишами
(стрелки, PgUp/PgDn, Home/End, Tab — другая вкладка). Кнопки: «Main menu» (если игра может продолжить),
«Copy report» (весь отчёт в буфер обмена, также Ctrl+C), «Open log folder», «Open report», «Quit game».

| Ситуация | Что происходит |
| --- | --- |
| краш при запуске игры (в том числе при загрузке модов, `haltGame` FML) | экран показывается, игра закрывается после «Quit game» |
| краш в игре | мир закрывается, экран показывается, можно вернуться в главное меню |
| краш встроенного сервера (одиночная игра) | то же, вместо закрытия игры |
| не хватает модов, мод для другой версии Minecraft, мод установлен дважды, циклические зависимости | вместо экранов Forge показывается этот экран со списком того, чего не хватает; отчёт сохраняется в `crash-reports` |

Распознаются: миксин не применился (какой миксин и из какого конфига), не найден класс, несовместимые
версии модов (`NoSuchMethodError` и подобные), нехватка памяти. Если миксин падает ещё до открытия окна игры,
показать экран нельзя — тогда остаются отчёт и логи.

Если игра падает ещё до создания своего окна (например, миксин ломается при загрузке классов Minecraft),
показывается обычное окно Java с тем же разбором проблемы и отчётом, кнопками «Copy report»,
«Open log folder», «Open report» и «Close»; отчёт сохраняется в `crash-reports`. Игра ждёт, пока окно
не закроют. На macOS это окно не показывается: там окна Java при запуске Minecraft могут зависнуть.

Если стоит BetterCrashes, краши ловит он (как и раньше), а подменяется только его экран.
Всё отключается опцией `crashScreen/replaceCrashScreen` в `logs.cfg`.

На каждый запуск игры создаются свои файлы, в имени — дата и время запуска:

| Файл | Что в нём |
| --- | --- |
| `All 22 October 08:14.log` | весь лог целиком, со всем мусором (как `fml-client-latest.log`) |
| `Errors 22 October 08:14.log` | только ошибки и исключения, сгруппированные по источнику |
| `Warnings 22 October 08:14.log` | только предупреждения, сгруппированные по источнику |
| `Crash 22 October 08:14.log` | только суть краша: что упало, исключение, моды в стектрейсе |
| `All crash 22 October 08:14.log` | краш-репорт целиком |
| `Loading 22 October 08:14.log` | время загрузки: этапы, самые медленные моды и шаги, сравнение с прошлым запуском |
| `Mods 22 October 08:14.log` | сводка сборки: Java, Minecraft, Forge, память, видеокарта, список модов и изменения с прошлого запуска |

`Errors`, `Warnings` и `Crash` создаются, только если в них есть что писать.

При запуске логи прошлых запусков, лежащие в папке, упаковываются в `Backup 22 October 08:14.zip`
(в имени — время того запуска) и удаляются из папки, так что в ней лежат только логи текущего запуска
и архивы. Хранятся 5 последних архивов, это меняется в `general/maxBackups`.
В Windows двоеточие в имени файла запрещено, там время пишется как `08-14`.

**Errors и Warnings** обновляются во время игры (раз в пару секунд) и устроены так:

- в начале таблица источников (лог или мод) с числом сообщений, самые шумные сверху;
- дальше раздел на каждый источник;
- одинаковые сообщения пишутся один раз со счётчиком `x27 (last 17:51:29)`; сообщения,
  отличающиеся только числами или адресами объектов, тоже склеиваются, несколько примеров
  показываются под `similar messages`;
- у исключения короткий стектрейс: место, где оно брошено, кадры модов, а кадры Java, Forge
  и лаунчера свёрнуты в `... N internal frames`; в заголовке — jar-файлы модов из стектрейса;
- в `Errors` попадают ERROR и FATAL, исключения уровня INFO, вывод в `System.err`
  (`printStackTrace` собирается обратно в одно исключение) и строки вида `[CTM/ERROR]` от MCPatcher;
  в `Warnings` — WARN. DEBUG и TRACE (в том числе их исключения) остаются только в `All`.

**Crash** пишется при любом краше, для которого Minecraft сохраняет краш-репорт
(в том числе если BetterCrashes позволяет продолжить игру — тогда краши нумеруются в одном файле):
описание («Ticking entity»), исключение и его первопричина, моды в стектрейсе (первый — самый вероятный
виновник), короткий стектрейс и подробности упавшего объекта (сущность, блок, экран).
Описание мира, системы и список модов в него не попадают — они есть в `All crash`.

**Loading** собирается из шагов прогресс-бара FML (`Bar Step: PostInitialization - GregTech took 3.930s`),
которых в обычном логе тысячи:

- общее время загрузки и сравнение с прошлым запуском;
- основные этапы (Construction, PreInitialization, Initialization, PostInitialization, LoadComplete,
  загрузка текстур и ресурсов) и их части;
- 30 самых медленных модов с разбивкой по этапам и изменением относительно прошлого запуска;
- моды, ставшие медленнее на 0.5 с и больше;
- самые медленные шаги загрузки ресурсов, текстур и рендера.

**Mods** пишется после загрузки модов: версии Java, Minecraft и Forge, система, число потоков процессора,
доступная память и параметры памяти/GC из аргументов JVM (остальные аргументы не пишутся — в них бывают
пути и токены), видеокарта и драйвер (дописываются при открытии главного меню), список модов
(название, id, версия, файл, отметка о выключенных и сломанных) и что добавлено, удалено
и обновлено с прошлого запуска.

Данные прошлого запуска для сравнения хранятся в `config/GTNHTweaks/logs-loading-stats.properties`
и `config/GTNHTweaks/logs-mods.properties`.

Начало лога, записанное до загрузки мода, копируется из `logs/fml-client-latest.log`,
поэтому файлы покрывают весь запуск.

Настройки в `config/GTNHTweaks/logs.cfg`:

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `general/folder` | `GTNHTweaksLogs` | папка для логов в корне Minecraft |
| `general/maxBackups` | `5` | сколько архивов `Backup ... .zip` хранить; `0` — удалять старые логи без архива |
| `files/writeAll` | `true` | файл `All` |
| `files/writeErrors` | `true` | файл `Errors` |
| `files/writeWarnings` | `true` | файл `Warnings` |
| `files/writeCrash` | `true` | файл `Crash` |
| `files/writeFullCrash` | `true` | файл `All crash` |
| `files/writeLoading` | `true` | файл `Loading` |
| `files/writeMods` | `true` | файл `Mods` |
| `details/maxStackFrames` | `12` | сколько кадров стектрейса оставлять на исключение в `Errors` и `Warnings` |
| `details/maxCrashStackFrames` | `30` | то же для `Crash` |
| `details/stderrAsErrors` | `true` | считать вывод в `System.err` ошибками |
| `details/ignore` | пусто | регулярные выражения: подходящие сообщения не пишутся в `Errors` и `Warnings` (остаются в `All`). Проверяется строка `источник: сообщение`, например `Angelica: Frame pacing.*` |

### backups: плашка бэкапа ServerUtilities

Когда ServerUtilities начинает бэкап мира, в правом верхнем углу выезжает плашка в стиле достижений
из новых версий Minecraft (в цветах темы GTNH):

- иконка дискеты, на которую «записываются» строки, пока идёт бэкап;
- заголовок «Backing up the world», время бэкапа и примерное оставшееся время;
- полоса прогресса с процентами и бегущим бликом;
- в конце плашка становится зелёной («Backup complete», сколько длился бэкап и размер архива) или красной
  («Backup failed»), звучит звук, через несколько секунд плашка уезжает.
  Плашка видна и в открытых меню, скрывается по F1.

Откуда берётся прогресс:

- **GTNHTweaks на сервере** (и в одиночной игре): сервер следит за логом ServerUtilities
  (`Backing up 4306 files...`, `[374 | 8.68%]: ...`, `Backup done in 00:41 seconds (2.0GB)!`)
  и отправляет игрокам точный прогресс. Игрок, зашедший во время бэкапа, тоже видит плашку.
  В одиночной игре прогресс передаётся напрямую, без пакетов, поэтому плашка обновляется,
  даже если игра стоит на паузе.
- **Сервер без GTNHTweaks**: бэкап распознаётся по сообщениям в чате (ключи перевода ServerUtilities
  вроде `...backup_start` или текст сообщения), прогресс оценивается по длительности прошлого бэкапа
  на этом сервере (`config/GTNHTweaks/backups-stats.properties`). Если прошлого бэкапа нет,
  по полосе бегает индикатор без процентов.

Сообщения ServerUtilities о бэкапе в чате по умолчанию скрываются: их заменяет плашка.

Настройки в `config/GTNHTweaks/backups.cfg`:

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `general/theme` | `SHADOW` | тема: `SHADOW`, `DARK` или `LIGHT` |
| `general/playSound` | `true` | звук в конце бэкапа |
| `general/hideChatMessages` | `true` | скрывать сообщения о бэкапе в чате |
| `general/finishedToastSeconds` | `6` | сколько секунд плашка висит после бэкапа |
| `general/timeoutMinutes` | `30` | убрать плашку, если о бэкапе ничего не слышно столько минут |
| `detection/detectFromServerLog` | `true` | серверная часть: следить за логом ServerUtilities |
| `detection/detectFromChat` | `true` | клиентская часть: распознавать бэкап по чату |
| `detection/loggers`, `keywords`, `ignored`, `failed`, `finished`, `started` | см. файл | регулярные выражения, по которым распознаются сообщения о бэкапе; можно подстроить под свой язык или версию ServerUtilities |
| `text/*` | английский | подписи на плашке, поддерживается кириллица |
